# yt-bp-claud-code-skills

Набор Agent Skills для автоматизации полного цикла задачи из Яндекс Трекера: от планирования до merge request.

## Что внутри

- `yt-task-orchestrator` — единая точка входа, роутит задачу по статусу.
- `1. yt-task-plan` — анализ задачи, подготовка плана и `agent_meta`.
- `2. yt-task-work` — реализация изменений в коде.
- `3. yt-task-review` — проверка качества и соответствия acceptance criteria.
- `4. yt-task-deploy` — подъем окружения и проверка деплоя.
- `5. yt-task-test` — запуск тестов и фиксация результата.
- `6. yt-task-mr` — создание MR, ожидание CI, merge и завершение.

## Рекомендуемая точка входа

Использовать `yt-task-orchestrator` как единственный entrypoint.

Он:
- получает задачу по ключу;
- читает текущий статус и `agent_meta`;
- вызывает нужный этап пайплайна;
- останавливает цикл при неизвестном статусе или превышении лимита попыток.

## State Machine

Цепочка статусов:

`Требуется оценка -> Оценка задачи -> Взять в работу -> В работе -> Готово к ревью -> Ревью -> Подтвержден -> Деплой -> Можно тестировать -> Тестируется -> Готово к релизу`

Переходы выполняются самими skills и фиксируются в `agent_meta.status_history`.

## Единый контракт `agent_meta`

Все этапы используют общую структуру:

```yaml
agent_meta:
  branch: agent/task-name
  status_history: []
  plan:
    - ...
  acceptance_criteria:
    - ...
  risks:
    - ...
  dependencies:
    - ...
  last_error:
    stage: ""
    message: ""
  attempts:
    work: 0
    test: 0
    deploy: 0
```

## Политика ретраев

- `work`, `test`, `deploy` увеличивают соответствующий счетчик попыток.
- При превышении лимита (`> 3`) добавляем к задаче комментарий об ошибке и добавляем "@vitaliy.gusev" и завершаем.
- На успешном этапе `last_error` очищается.
- На ошибке обязательно заполняются:
  - `last_error.stage`
  - `last_error.message`

## Интеграции

- Трекер: `yandex-tracker-mcp@latest`
- MR/CI: инструмент репозитория проекта (например, claude-glab-skill, используемый в `yt-task-mr`)

## Быстрый сценарий использования

1. Передать ключ задачи в `yt-task-orchestrator`.
2. Оркестратор сам вызовет нужный этап по статусу.
3. Повторно запускать оркестратор до финального статуса.

## Ответственность этапов

- `yt-task-plan`: формирует план, AC, риски, зависимости, оценку и инициализирует `agent_meta`.
- `yt-task-work`: реализует изменения, коммитит и пушит ветку.
- `yt-task-review`: проверяет AC/качество, отправляет в доработку или в деплой.
- `yt-task-deploy`: поднимает docker-контур, валидирует healthcheck.
- `yt-task-test`: выполняет тесты и останавливает docker в обеих ветках (успех/ошибка).
- `yt-task-mr`: создает MR, ждет CI, мержит и закрывает задачу.
